# Handoff: running 1000pets locally

## Get the code and run it
```bash
git clone https://github.com/donkimc/1000pets.git
cd 1000pets
npm install
npm test            # 283 tests (about 4 minutes)
# put keys in .env.local (git-ignored; copy .env.local.example), then:
npm run dev     # http://localhost:3000, loads .env.local
```
Node 20 or newer (built on Node 22). Without API keys the world, pets, chat gate and dashboard still run,
but System 2 (slow thinking) and pet replies are off.

Production build, as Railway runs it: `npm run build && npm start`.

## Environment variables
| Name | Default | Purpose |
|---|---|---|
| `GROQ_API_KEY` | none | Primary thinking model (`openai/gpt-oss-120b`, free tier) |
| `DEEPSEEK_API_KEY` | none | Fallback model (`deepseek-chat`) |
| `LOCAL_LLM_MODEL` | none | Local OpenAI-compatible model (Ollama, LM Studio), tried first. Setting it turns it on |
| `LOCAL_LLM_BASE_URL`, `LOCAL_LLM_TIMEOUT_SEC`, `LOCAL_LLM_CONCURRENCY` | `http://localhost:11434/v1`, 90, 1 | Timeout counts only once a request is being served, not while it waits in line. The local model serves one request at a time; extra calls queue first come, first served (see `S2_PATIENCE_SEC`) |
| `RULE_LEARNING` | off | Set to `on` to let pets try tuning their own habits (see Habits below). Also a switch at the top of the Pets tab; the setting is saved with the simulation |
| `S2_PATIENCE_SEC` | 240 | How long a pet's slow thought waits in line for the local model before falling through to Groq/DeepSeek. Chat replies wait 20 s, speech 45 s, gists and dreams 120 s |
| `DEEPSEEK_BUDGET_USD` | 1 | Pets stop using DeepSeek once estimated spend reaches this. Kept in `DATA_DIR/llm-spend.json`, so loading a save never resets it. The Teacher is not limited by it |
| `TEACHER_REVIEW_SIM_MIN` | 180 | Simulated minutes between teacher reviews |
| `TEACHER_REVIEW_MIN_REAL_SEC` | 600 | Real-time gap between reviews, so fast speeds cannot flood the model |
| `TEACHER_MAX_CALLS_PER_HOUR` | 12 | Guard on teacher model calls per real hour (a count, not a dollar limit) |
| `TEACHER_QUESTION_GAP_MIN` | 180 | A pet may ask the Teacher at most one question per this many simulated minutes (was 60) |
| `S2_GATE` | on | `off` makes pets think on the clock again instead of skipping a thought when nothing is new (see Fewer thoughts below) |
| `S2_DEEP_EVERY` | 8 | Every Nth made thought is a deep review (was 4); 0 turns them off |
| `S2_DEEP_PROMPT` | compact | `full` gives the deep review the old full prompt |
| `CHAT_MAX_REPLIERS` | 2 | A message to everyone is answered by this many pets at most (the nearest) |
| `GROQ_MODEL`, `DEEPSEEK_MODEL` | see above | Override the models |
| `S2_PROMPT` | compact | `full` brings back the original System 2 prompt exactly (use it if the compact prompt turns out to hurt thinking or beliefs); see Compact prompt below |
| `S2_INTERVAL_SEC` | 70 | Real seconds between a pet's slow thoughts (randomised 0.8-1.3x), counted from when the last one finished. A local CPU model needs about 150 |
| `DATA_DIR` | `./data` | Where JSON logs and snapshots are written (`/data` volume on Railway) |
| `SEED` | 12345 | World and pet random seed |
| `RESUME_PASSWORD` | 1234 | Resuming the simulation asks for this (pausing never does), so a restart or a stranger cannot start the world and spend model calls. Plain text and no lockout: it is a latch, not security. Set it to something else, or to nothing (`RESUME_PASSWORD=`) to switch it off |
| `START_PAUSED` | on when hosted (Railway), otherwise off | `on` makes every start begin paused anywhere, `off` lets a hosted copy start running. Whatever the setting, a pause you set is saved and kept across restarts |
| `LAYOUT` | house (new runs), the saved plan (old runs) | Floor plan: `house` (4 rooms) or `legacy` (the original single room). A run saved in the single room stays there unless you set `LAYOUT=house`, which moves it into the house (pets start in the living room). Or start a new run with `RUN_ID=house` |
| `RUN_ID` | main | Folder name under `DATA_DIR/runs/` |
| `ADMIN_TOKEN` | none | If set, speed/pause/add-pet endpoints need header `x-admin-token` (the page has no field for it yet) |

Never commit keys. On Railway they are service variables on the `1000pets` project.

## Layout
- `src/layout.ts` the floor plan as data: rooms, walls (with door gaps), doors, furniture, a hum pitch per charger; `HOUSE` (4 rooms) and `LEGACY` (the first room, unchanged). `src/nav.ts` path finding for the Teacher and the human (pets never use it). `src/acoustics.ts` how sight and sound get round walls
- `src/clock.ts` simulation clock (1x, 10x, 100x, 1000x), independent of wall time
- `src/world.ts` rooms, sun, weather, temperature, curtain, door, lamp, heater, noises
- `src/sim.ts` advances world and pets in fixed 5 s chunks (deterministic for a seed)
- `src/sensors.ts` virtual sensors; pets never read world state directly
- `src/system1.ts` fast rule-based decisions and drives; `src/system2.ts` slow LLM thinking
- `src/llm.ts` provider order local, Groq, DeepSeek; honours rate-limit replies; per-provider budget ceiling and concurrency; teacher calls are accounted separately and ignore the ceiling
- `src/speech.ts`, `src/conversation.ts` spatial speech, claims, System 1 speaking gate; the teacher is a third kind of speaker
- `src/teacher.ts` the AI teacher: body, long-term plan and agenda, lessons, answers to pets' questions, review every 3 simulated hours, may change the environment. Always uses DeepSeek first, local model last
- `src/world.ts` `setOverride` pins an environment value (lamp, heater, curtain, door, weather, sun, temperatures) until released to auto; changes are logged to `env-changes.jsonl`
- `src/saves.ts` named simulation saves (`DATA_DIR/saves`) and the brain library (`DATA_DIR/brains`); `src/brain.ts` brain export/import (times stored as ages, so a brain works in a sim with a different clock)
- `src/scenes.ts`, `src/cues.ts`, `src/sleep.ts`, `src/dreams.ts`, `src/predict.ts`, `src/verify.ts`, `src/rules.ts` the brain features described below (scene memory, hum learning, consolidation, dreams, surprise, verification, habits)
- `src/relations.ts` who a pet knows and how it rates them (see Relationships below)
- `scripts/bench-local-model.ts` compares local models on real pet prompts
- `src/server.ts` HTTP, WebSocket and APIs; `public/` is the mobile site (Tailwind, built to `public/app.css`)
- `config/pets.json` pet names, colours, traits (source of truth, applied at every start)
- `AGENT.md`, `README.md` the original concept and design rules

Phases 1-7: scaffold and deploy, 2D world and environment, three pets with sensors and System 1,

## Added later
Environment control and history (Env tab), save/load of the whole simulation (Saves tab; loading pauses the sim and keeps an automatic backup), per-pet brain save/download/upload/apply, and the AI teacher (Teacher tab). Pets ask the teacher through an `ask_teacher` field in their System 2 reply. Brains restored into a default pet keep their traits across restarts (`brainTraits`).

Scene memory (`src/scenes.ts`): pets also have a short-range all-around "near" sense (`sensors.ts`) and keep salient moments (found the charger, sunlight patch, bump, sudden light or temperature change, battery low, company) as small structured scenes: things seen and felt, a text-art view, body state, and a dead-reckoned place in the pet's own frame (never world coordinates). 24 are kept, forgetting lowest importance and oldest first; the best 4 go into System 2's notes, and each records how often it was used (groundwork for sleep consolidation). Scenes travel in brain files (without their place). The prompt shows 3 scenes, without the text-art.

The charger hum (`src/cues.ts`): the charger emits a steady tone (534 Hz, its own sensor channel, audible from any direction out to 700 units, louder when closer; switch it off with `beaconOn` in the Env tab). Pets are never told what it means. Each pet counts evidence per pitch: charging that began soon after it was close to the tone's loud end is support; following the tone to the source and not being charged is contra (not counted if it stopped following on its own or another pet is beside it). Two successes and mostly successes means trusted. System 1: an unfamiliar tone pulls curious, bold pets toward it (fading as they get used to it); with low battery a trusted tone is followed; System 2 can urge it with the `follow_tone` suggestion. Following steers round obstacles and gives up for 3 minutes if it makes no progress. Hum knowledge travels in brain files. Measured over 14 simulated days: with the hum off versus on, median time from battery below 45% to charging is 65 versus 40 minutes (mean 131 versus 81), and aimless light-seeking falls from about 25% of time to under 1%.

Sleep consolidation (`src/sleep.ts`): once a pet has slept 15 simulated minutes, a rule-based pass runs inside the sim (no model, deterministic): repeated moments are merged into at most 2 examples per kind that remember how often it happened, unused moments fade and faint old ones are forgotten (important ones, used ones and ones backing a young gist are kept), what the pet was told is marked "supported" once it has experienced something of that kind afterwards (keyword to kind table, `kindsFor`), and belief and gist confidence move with counted evidence. Then one slow model call per sleep (the Consolidator; local first, waits a minute if busy, then Groq, then DeepSeek, which counts toward the pets' ceiling) writes up to 3 provisional "gists" that must cite real moments and start at 50% at most; a gist gains confidence only from later experience. Gists appear in System 2's notes, the Pets tab, the S3 entries of the thought log, and travel in brain files. Limitations: claim checking is keyword based, nothing is ever marked contradicted, and nothing yet resolves conflicting gists.

Dreams (`src/dreams.ts`): right after each night's consolidation a pet dreams, by rules and deterministically: two real moments, picked with a lean toward trouble (flat battery, bumps, darkness), mixed with one or two twists (exaggerate, remove the hum and pad, swap place or colour, another pet in the way, blend), plus a concrete worry derived from them ("the tone or the pad might not always be there"). A model then narrates it in the background (same providers as gists; the pet's world is spelled out and narrations that mention phones, books, screens and the like are rejected, leaving the plain rules version). Dreams live in `mind.dreams`, apart from beliefs, claims, moments and gists. System 2 sees only the latest one for 12 simulated hours, labelled "NOT something that happened", and is told to turn a worry into a question or an intention, never a belief; a guard (`copiesDream`) drops any belief that merely repeats a dream's invented twist. The Teacher sees recent dreams in its review. Dreams show in the Pets tab, the thought log and brain files (without the moments they came from).

Prediction and surprise (`src/predict.ts`): each pet learns, from its own sensor stream, what usually happens next on a few channels (light, temperature, battery per tick, learned separately for what it was doing during that tick; the tone's loudness, learned separately for walking toward it, walking about, and standing still; whether a tone it was hearing keeps being heard), as a running mean and spread over roughly the last 40 simulated minutes, with outliers clipped so one wild jump cannot numb it. Nothing is a built-in constant about the world. A reading far outside what it expects (about 3+ standard deviations, once it has 30 observations) is a surprise with a score 0..1 and a reason in its own words. The tone's presence uses counts: a tone at 0.3 or louder that stops, or appears, in one tick cannot be explained by walking (the most it changes per tick is about 0.21). "Reached the loud end of the tone and was not charged" is scored from the pet's own record of how often that works, judged before the failure is counted. Surprises make a scene when they are tone events or no-charge (kinds `tonelost`, `toneback`, `tonedrift`, `nocharge`, importance 0.5 + 0.4 x score), appear in System 2's notes ("what has surprised me lately", "how well I can predict things", what it has learned about the tone), steer dreams toward unexpected moments, lift curiosity by up to 0.1 each, and strong ones (score 0.5+) are logged as S3 `surprise` thoughts. The 15-minute metrics record each pet's peak surprise (chart on the Dashboard). Learned expectations travel in brain files; recent surprises do not. Measured: with the hum switched off then on, every pet that could hear it was 100% surprised both times; in an undisturbed week, tone-related surprises are 0 and light/temperature ones trend down; time to charge is unchanged (median 40 min).

Verification (`src/verify.ts`, applied nightly in `src/sleep.ts`): what a pet was told (including by the Teacher), believes, or has concluded (gists) is checked against its own experience. A statement is matched to a small set of testable topics, each with an evidence rule returning supported / contradicted / unclear, with a reason and whether it rests on counted positive evidence: the tone leads to the pad (charger moments while a tone was audible against no-charge moments; "always/never/only" is held to 30% failures, others to 50%), the tone is steady (tone-lost moments; "never" needs 6 hours of listening to bear it out and a single stop contradicts it), walking toward the tone makes it louder or quieter (the learned rate, direction-aware), the pad stays in one place (spread of where it was found, only comparing moments within 6 hours because dead reckoning drifts), the pad is by the heater (a pattern over at least 3 warm moments, 2/3 near or 2/3 far), and three simple cause-and-effect claims (the pad charges, the heater warms, the lamp or sun brightens) which can only be borne out. Anything else stays unverified: there is no keyword guessing. A contradicted claim is marked with its reason and recorded in `mind.refuted`; a contradicted belief or gist loses 60% of its confidence, is flagged, and is let go 4 hours later; a belief found wrong cannot be taken up again for 24 hours, and repeating a flagged one does not revive it. Verdicts outlive the evidence (moments fade) and only newer positive evidence can overturn them. Duplicate gists merge; a statement and its denial leave the weaker one weakened. The Teacher's review is shown which of its own claims the pets found wrong and told to correct them honestly. Pets see all of this in their notes ("WRONG", "my own experience disagrees"). Verdicts and the refuted list travel in brain files. Measured in simulation (3 seeds, 3 pets, false Teacher claims injected): the false heater claim was contradicted in all 9 pet-runs (days 1-8), "the humming never stops" in all 9 within about 1.5 days of the first time the hum was switched off, the true claim was supported within a day, and no false claim was ever marked supported.

Habits (`src/rules.ts`, off by default): seven soft thresholds in System 1 are now habits a pet may tune within hard limits (tiredness before sleeping by day and by night, how drained before seeking charge, how lonely before seeking company, how curious before inspecting, the pause between inspections, the pull needed to follow an unfamiliar tone). Reflexes are not habits and cannot be touched: obstacle avoidance, powering down at zero, and the critical-battery override (batteryLow is capped below it). With the setting off, behaviour is exactly as before. With it on: after a pet has watched itself for a day, an unmet need proposes a small step on the habit that actually limits it (a need hovering just under its trigger suggests lowering the trigger; curiosity already high suggests a shorter pause between inspections; a battery often low suggests seeking charge sooner), or System 2 may suggest one in a `tune` field (only mentioned in the prompt when learning is on). A proposal is a 24-hour trial: the habit alternates between new and old value every 2 hours so day and night are shared fairly, and each block records how the pet fared. It is kept only if the one measure the habit mainly affects clearly improved (at least 5 of 6 paired blocks, a small average gain, and a paired t of at least 2) while overall wellbeing did not get worse and the battery was not low more often; otherwise it is undone. Dormancy while the new value is in force aborts it at once and blocks that direction for 3 days; a clearly worse trial blocks it too; a flat inconclusive trial doubles the next step in that direction (up to 4 steps) so the search can cross a region where small changes make no difference. Everything is logged as S3 `habit` thoughts, shown on the pet card ("Its own habits") with a Reset button, and kept habits travel in brain files. Measured honestly (4 seeds, 14 days; and 2 seeds, 8 weeks): with learning on, nobody ever went dormant and wellbeing was unchanged in the normal world (0.635 on versus 0.638 off), because the defaults are already close to what the pets need and these habits move wellbeing very little (deliberately bad habits cost only about 0.018). Starting from those bad habits, learning moved them in the right direction (socialAt stepping down from 0.8) in 3 of 6 pet-runs over 8 weeks, but wellbeing stayed at about 0.62 with learning on or off. So it is safe and statistically honest, but in this world it finds little to improve; it matters more if the world or the pets' needs change.

Relationships (`src/relations.ts`): a pet comes to know the others as individuals, but only the way it could: by how they look. It is never given names or identities. Each moving thing it sees is matched to an acquaintance by hue (within 8 degrees; up to 8 kept), labelled by colour ("the green one"). For each it counts time in view, time within company range while it was lonely, and bumps (a bump is put down to the nearest one in view, once per 20 s; a pet that cannot see who it touched does not guess). A claim is owned by whoever the pet could *see* saying it (`canSee`, in the vision cone and range); an unseen voice belongs to nobody. The Teacher announces itself, so its claims are always owned by "the Teacher"; once the pet sees it speak, that look is learnt as the Teacher. When the nightly check settles a claim (supported or contradicted), the one who said it is credited, once per claim and recounted if the verdict flips. Trust is (right + 1) / (right + 2 x wrong + 2), so 0.5 means no record and a wrong claim weighs twice a right one. Affinity (-1..1, 0 until 5 minutes of watching) is time in good company against time seen, minus bumps per hour of company. Effects: System 2's notes list who it knows with their record and tag each claim with its source's reliability; System 1 chooses whom to approach when lonely by distance discounted for better company (up to 40%). Relationships travel in brain files and show on the pet card ("Who it knows", with who they really are for the viewer). Measured honestly: first version also made pets avoid those they bump into, and wellbeing fell (0.630 versus 0.636) because pets brush against each other about 9 times an hour without harm, so pets are never made to avoid anyone; with the final version wellbeing is 0.636 (baseline 0.638, 4 seeds, 14 days). In simulation each pet forms 4 acquaintances (two pets, the human and the Teacher) within a day. Limitations: trust only moves on testable claims (see Verification), so with the current few topics most sources have no record; identity is by hue only, so two pets of the same colour would be confused.

Rooms and doors (`src/layout.ts`, `src/acoustics.ts`, `src/nav.ts`): the house is four rooms of 1000 x 700 (living room = the original room, same coordinates; kitchen, bedroom, study), joined by four doors in a loop. Each room has its own charger (every one hums at its own pitch, each on its own semitone bin), window, lamp, heater and furniture. Walls and shut doors stop movement and sight (`blockedAt`, `crossings`); sound is muffled to 35% per wall or shut door, and a charger round a corner seems to come from the doorway (a walking-distance field per charger, `Acoustics`), so the hum leads a pet to the door. Every door starts shut, closes by itself two minutes after it was opened (not on someone in the doorway), and can be locked (Env tab, or the Teacher with `doorLocked`). People open doors by walking up to them. A pet pushes one open on purpose (System 1 action `open_door`) when it is heading for a doorway: after a tone, or out of curiosity (`explore_door`, once in a while, bolder and more curious pets more often). A pet sees a doorway as a still object with a flag open or shut, and feels a shut door as a touch (`door`); it is never told which room it is in. Each room has its own temperature, lamp, heater and curtain (the first room's are the world's `env` fields; the others are `snap.rooms`), the same weather for all; open doors let rooms trade warmth; the Teacher and you can set one room's value (`room` on an env change). Voices are muffled by walls too (`inEarshot`). Pets keep a small top-down map of the ground around them in each remembered moment (`grid`, 9x9 cells of 40 units, ahead is up: wall, furniture, shut door, open doorway, bodies; it comes from short-range sensing, not from the plan). Dead reckoning now measures how far the body really moved (sliding along a wall used to be counted as walking straight on, so the position drifted by thousands of units a day) and is pulled back to where a pad was first found each time the pet stands on that pad again (pads are recognised by their hum). "The pad stays in one place" is judged per pad. The Dashboard shows rooms when there are several: each room right now (who is in it, temperature, lamp, heater, curtain, share of all pet time), each pet's time per room as a bar with its room changes, doors it pushed open itself and where it charged, a "who was where" strip (one block per 15 simulated minutes), and a temperature line per room. Doorways are 120 wide (90 snagged a first-person walker who did not aim), and a pet that finds itself at a shut door usually pushes it open (about 60-95% of the time by character) instead of turning away. Measured (2 seeds, 4 days, 3 pets): every pet visited 3 or 4 rooms and went through doors 70-140 times, nobody ran flat, wellbeing 0.61 (0.636 in the single room, because company is harder to find). Strong surprises per 3 days rose from 205 to 293, mostly the hum appearing and fading as pets change room.

The 3D view (`public/world3d.js`, three.js served from `/vendor/three`, `public/view.js`): a blocky, textured picture of the same world, drawn from the same state; it changes nothing in the simulation. Lights follow each room's lamp and daylight; doors swing; pets show a battery bar and speech bubbles. Cameras: Walk (first person: drag to look, stick or WASD to move, Q/E or arrows to turn; the body faces where you look), Top (tap the floor to walk there), Follow a pet, and Pet's eyes. A minimap sits in the corner (bigger with the map button) and the full map is below; tapping either walks you there through the doors (route found by `nav.ts`, dropped as soon as you touch the controls). Full screen works. On wide screens the 3D view and the map sit side by side.

Voices (`public/voice.js`, all in the browser): Kokoro (speaking) and Whisper tiny (listening) are downloaded from a CDN once and cached. Every pet and the Teacher has its own voice (`voice` in `config/pets.json`, `VOICES` for new pets, `TEACHER_VOICE`), with pitch and speed for the browser's own voice, which is used while Kokoro loads, if it is switched off, or when Kokoro is not keeping up. You hear only what is near your avatar: loudness by distance and walls, panned to the side the speaker is on; "hear everyone" overrides that, and a pet answering you from far away comes over the radio (band-passed, with beeps). Talking is a walkie-talkie: hold the button (Talk tab, or the small mic in the 3D view, or the space bar), speak, let go; beeps mark the start and end; start with a pet's name to talk to that pet; the radio carries your voice anywhere. Tested in a real browser: Kokoro speaks clearly on the processor (about 3.5 seconds to make a second of speech while the page was also drawing 3D on a 4-core machine, hence the fallback), and Whisper tiny transcribed Kokoro's own speech correctly. On the graphics chip (WebGPU) Kokoro was fast (0.65 s per second) but the sound it produced was garbage (samples far outside -1 to 1), so that is opt-in, checked for sanity, and falls back to the processor.

Places (`src/places.ts`): a pet makes a small map of its own, with no walls and no names. Its landmarks are the charger pads it has stood on (told apart by their hum) and the doorways it has stepped through; each is a point in its own dead-reckoned frame (pads are pulled to where it first reckoned them, doorways within 230 units are the same doorway). Between landmarks it remembers the way it actually walked, as breadcrumbs reduced to the turns that matter, kept only if the walk was no more than 4 times the straight distance, under 1800 units and within 30 minutes; a shorter way replaces a longer one. For each pad it counts the times charging began there; standing on a pad for a minute without charging gives that pad up for an hour. When the battery is low and no hum is leading it (there is none, or it is giving up on it), System 1 reads the map (action `go_to_place`): the cheapest known way from the landmark it last reached to the nearest pad (a little favouring ones it has charged at), then it walks that way landmark by landmark, going round things in the way and pushing doors open; no progress for 150 s gives that pad up for an hour. System 2's notes list the pads where its battery filled up (never called chargers: the pet is not told what a pad is) (hum, times charged, how long ago, roughly how far and which way) and how many doorways it knows; a claim that there is more than one charger is borne out once it has found two (`more than one pad`). The Pets tab draws the pet's own map (chargers with hum and times charged, doorways, the remembered runs, where it thinks it is, and the route it is walking). Measured (hum switched off, battery at 25%, pets wherever they happened to be, 48 trials over 2 seeds, after 3 simulated days of learning): with the map 37 of 48 reached a charger within 40 minutes (median 145 s and 495 s), without it 33 of 48 (median 675 s and 925 s). After about a day and a half a pet's map had exactly the 4 pads (by their 4 hum pitches) and 4 doorways of the house. Limits: a map is in the body's own frame, so it does not travel in brain files (a restored brain keeps no places); poses drift a little between pad visits; there is no way yet for pets to tell each other where a charger is, and a pet that has never seen another room knows nothing of it.

Save files (Saves tab, `src/saves.ts`): every save can be downloaded as one gzipped file (`.1000pets`: the clock with its pause, world, pets, teacher, logs and thoughts), and "Load from a file…" uploads one (up to 300 MB), adds it to the list as "<name> (uploaded)" and asks before it replaces the live world (a backup of what you had is kept, and the sim stays paused). "Save and download a file" does both in one step. This is how to move a run between machines, for example from the hosted site to your own: nothing syncs by itself. An uploaded file is checked before a byte is kept: it must be a 1000pets bundle, hold readable clock, world and pets files, and only logs and state files at most two folders down (no paths that climb out). Downloads are open like the saves list (set no secret in a run); uploads and loads honour `ADMIN_TOKEN`.

Spending ledger (`src/usage.ts`, Dashboard "Spending"): every model call is tagged with what it is for (`thought`, `deep`, `reply`, `speech`, `dream`, `gist`, `teacher-plan`, `teacher-review`, `teacher-lesson`, `teacher-answer`) and its pet, and the gateway reports every attempt at every provider (including failed ones, which cost nothing) with tokens in and out, the cached part of the input where the provider says (DeepSeek does), the estimated cost and the time. They are rolled up by simulated day, kind, pet and provider in `llm-usage.json` (with the run, so saves and downloaded files carry it) and appended raw to `llm-calls.jsonl`. The Dashboard shows the totals, the last hour, the pace (projected cost and tokens a day once there are about 10 calls in the last hour) and how long the pets' DeepSeek ceiling lasts at that pace, tokens by kind, pet and model, tokens per simulated day, and the latest calls. `GET /api/usage` is the same data. It only observes: it changes nothing a call does.

Cost bench (`npm run bench:cost -- --days 2 --seed 1 [--speed 1] [--json file]`): runs the real thinking, speech, Teacher, sleep and dream code and prompts against a stub model that gives valid canned replies and counts tokens (characters / 4), priced at DeepSeek's list price, so it spends nothing and the same seeds can be run before and after a change meant to save tokens. Baseline before any saving (3 pets, house, seed 1, one thought every ~70 s of real time, everything paid as on the hosted site): about 6.1 million tokens and $1.81 per simulated day at 1x speed ($0.076 an hour, so the $1 ceiling lasts about 13 hours): slow thoughts 71% of tokens (2,400 a day, about 1,750 tokens in and 60 out each in the bench; the real model writes about 150 out), deep thoughts 25% (a deep thought sends no more than a slow one), Teacher answers 2%, everything else under 2%. Saved baselines are in `docs/baselines/`.

Compact prompt (cost phase B, `S2_PROMPT`): a routine slow thought used to send everything the pet knows (about 1,750 tokens in). The compact prompt sends the same kinds of fact, fewer of each, said more briefly, and in a different order, and asks for a shorter answer (450 tokens at most instead of 900). Per thought it keeps: personality; the 2 others it knows best; the 2 pads it uses most and how many doorways it knows; its best tone knowledge; the top 2 sleep gists; all its beliefs (so it can retract any), the last 3 claims, the last 2 things found wrong; and then what changes by the minute: the clock, body and needs, senses (2 things seen, 2 within reach), the 2 most recent surprises, a dream if it is recent, the 2 most useful memories in one line each, the last 4 events (routine idling left out), its recent questions, the repeat warning, its intention. Every rule of the system text is kept (JSON only, plain-words beliefs, no numbers copied, nothing from a dream becomes a belief, let go of what experience contradicts, say only if someone is near), and the text no longer names the pet, so it is identical for every pet. Order matters because DeepSeek bills the start of a prompt it has seen lately at about a quarter of the price: slow-changing facts come first and the clock last, and the pad timing is deliberately coarse so the start does not change every minute. A deep thought (every 4th) still gets the full prompt and the full 900-token answer. `S2_PROMPT=full` restores the old prompt for routine thoughts too, exactly. Measured with the cost bench (2 simulated days, seed 1, the provider's prompt cache modelled, everything paid): a slow thought's input fell from 1,768 to 1,007 tokens (-43%), slow thoughts from $1.05 to $0.59 a day, and the whole day from 6.08M to 4.32M tokens (-29%) and from $1.46 to $1.01 (-31%); deep thoughts are now 36% of the tokens and unchanged (Phase C). The bench's stub model cannot say whether the pets think as well on the shorter prompt: that is measured in the quality check (Phase E), and `S2_PROMPT=full` is the way back. Baselines: `docs/baselines/cost-phaseB-*.json`.

Fewer thoughts (cost phase C): (1) a pet whose situation has not changed since its last thought skips this one (`S2_GATE=off` disables). The situation is a short signature: room, mode, what it is doing in broad classes, battery and each need in bands, who is near, whether a tone is audible, touch, its last real event (routine idling does not count), how many memories and the newest, the newest surprise, claims, beliefs, dream, last sleep, intention. Same signature: no call, and the next thought waits 2, then 3, then at most 4 times the usual interval; any change thinks again at the next due time. Being asleep, charging or powered down is just a signature that does not change, so those stretches are skipped without a special rule. Skips are counted per pet and shown on the Dashboard. (2) The deep review is every 8th thought instead of 4th and uses the compact notes plus its last few thoughts and the same rules (`S2_DEEP_PROMPT=full` for the old prompt); its answer limit is unchanged. (3) The Teacher teaches and answers from the pet's compact notes (unless `S2_PROMPT=full`), may be asked a question by each pet only every 180 simulated minutes (was 60), and is guarded to 12 model calls an hour (was 30). (4) A message to everyone is answered by the nearest 2 pets, not every pet in earshot; a message to one pet is always answered by it. Measured with the cost bench (1 simulated day, seed 1, prompt cache modelled, everything paid): phase B state $0.99 and 4.25M tokens a day (3,189 slow thoughts); the gate alone $0.59 (1,899 thoughts made, 19% of due thoughts skipped, and because skipped thoughts also stretch the wait, 40% fewer calls overall); with the deep changes as well $0.48 and 2.07M tokens a day. From the very first baseline (about $1.46 a day with the cache, $1.82 without) that is about a third of the cost. The bench cannot say whether the pets think and learn as well on a third of the thoughts: that is the quality check (Phase E). Every change has its own switch (`S2_GATE`, `S2_DEEP_EVERY`, `S2_DEEP_PROMPT`, `CHAT_MAX_REPLIERS`, `TEACHER_QUESTION_GAP_MIN`, `TEACHER_MAX_CALLS_PER_HOUR`) so any one can be undone.

Movement now slides along obstacles when blocked, and the obstacle ray treats other bodies as wide as they really are (both fixed deadlocks where pets pushed into each other forever).

## Pictures for the README
`docs/screenshots/` holds the pictures used in README.md. `scripts/screenshots.ts` retakes them with the Chrome you have installed (puppeteer-core downloads nothing; it uses the graphics chip, because drawing the 3D view in software takes minutes a picture). Start a server of its own (its own `RUN_ID` and `DATA_DIR`, API keys blank, `LOCAL_LLM_MODEL` set if you want thoughts), let it run into the daytime, then `URL=http://localhost:3300 SCALE=2 npx tsx scripts/screenshots.ts`. Do not point it at a run you care about: it walks the avatar around and opens tabs.

## Running a local model well
Ollama (the macOS app) unloads a model after 5 idle minutes unless told otherwise: `launchctl setenv OLLAMA_KEEP_ALIVE 24h`, then quit and reopen the app (this lasts until you log out or reboot). Compare models on the pets' real prompts with `npm run bench:model -- qwen2.5:3b qwen2.5:1.5b` (needs the CPU to itself; it prints validity, speed and samples).

## Things to know
- Groq free tier limits (daily tokens) are enforced by Groq; the gateway backs off on its 429 and uses DeepSeek.
- The human avatar moves in real time, not simulated time.
- Pet speech rates are constants in `src/speech.ts` (`GATE`, voice ranges).
- Test servers in `/tmp` used a fake OpenAI-style provider; the real models have only been seen answering System 2 thoughts.
